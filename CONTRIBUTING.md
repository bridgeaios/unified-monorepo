# Contributing to the Unified Monorepo

Thank you for contributing! This monorepo unifies a frontend GUI, a backend API
gateway, and migrated project services into one system.

## How to add a new project

1. **Discover** — Run the project scanner to inventory the project:
   ```powershell
   pwsh ./Discover-Projects.ps1
   ```
   This writes `projects.json` (source of truth) to
   `%USERPROFILE%\Desktop\ProjectInventory\`.

2. **Consolidate** — Merge scanner output into the monorepo inventory:
   ```powershell
   pwsh ./scripts/discover/consolidate-inventory.ps1
   ```

3. **Categorize** — Determine stack, category, destination, and port:
   ```powershell
   pwsh ./scripts/discover/categorize-projects.ps1
   ```

4. **Check conflicts** — Detect port/dependency conflicts before migrating:
   ```powershell
   pwsh ./scripts/migrate/conflict-check.ps1
   ```
   If conflicts are found, resolve them:
   ```powershell
   pwsh ./scripts/migrate/resolve-conflicts.ps1 -AutoAssign
   ```

5. **Migrate** — Copy the project into `services/` (read-only on source):
   ```powershell
   pwsh ./scripts/migrate/migrate-project.ps1 -SourcePath <path> -ServiceName <name>
   ```
   Or batch-migrate everything:
   ```powershell
   pwsh ./scripts/migrate/migrate-all.ps1
   ```

6. **Register** — Add the service to the gateway registry:
   ```powershell
   Invoke-RestMethod -Method Post -Uri http://localhost:4000/services/register `
     -Body @{ name='...'; url='http://localhost:<port>'; stack='...'; category='...' } `
     -ContentType 'application/json'
   ```

7. **Track** — Add a row to `docs/MERGED_PROJECTS.md` and commit.

## How to register a service

POST to the API gateway:

```http
POST http://localhost:4000/services/register
Content-Type: application/json

{
  "name": "project-example",
  "url": "http://localhost:4001",
  "stack": "Node.js",
  "category": "Backend / Service",
  "port": 4001
}
```

## How to update Docker

Re-generate Dockerfiles and docker-compose from the categorized inventory:

```powershell
pwsh ./scripts/discover/generate-docker.ps1
```

Then rebuild:
```bash
docker-compose -f infrastructure/docker/docker-compose.yml up --build
```

## PR requirements

- `conflict-check.ps1` must pass (no port collisions).
- `run-all-tests.ps1` must pass (green test suite).
- All new services must have a `MIGRATION.md` marker (auto-generated by migration).
- Dockerfiles must be regenerated via `generate-docker.ps1` for containerized services.

## Code review process

1. Open a PR against `main`.
2. Required reviewers (see `.github/CODEOWNERS`) are auto-assigned.
3. CI runs: discover → analyze → build → test → conflict-check.
4. Once approved and green, merge. The migration job can then run (manual approval).
